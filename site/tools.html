Each tool keeps its own repository and release lifecycle. The farm tools, local utilities and utility suites have full tool guides on this site, and the suite utilities page says what each sah tool is for; follow each repository's source documentation for every flag, configuration key, and policy requirement.

adssh

Available

A programmable shell with policy evaluation, approvals, an HMAC audit chain, Starlark extensions, and an MCP server. The binary remains adssh.

Execution shell. Source documentation ↗

sash

Available

The login and emergency shell of the SAH fleet: one Go binary that runs a closed table of in-process filters and agent verbs under a signed grant. Its scripting language has pipelines, functions, structured errors, secret bindings that print as *** and cannot be passed to a verb, plan mode, --needs and --lint, and record and replay.

Host login shell. Docs for sash → · Source documentation ↗

The SystemAPI agent runs sash --session for an ordinary Linux terminal session today. Language v7 (path values, defer and finally, capture, z and jump) and service files for sahinit are in development.

vpscfgfarm

Available

Configuration and deployment gates for SSH fleets. A governor, reviewed contracts, and journals bound every permitted mutation.

Contracted fleet changes. Docs for vpscfgfarm → · Source documentation ↗

badfarm

Available

Inventory and assess hosts, containers, Kubernetes, and infrastructure code. Emit evidence and a reviewable remediation handoff.

Read-only discovery. Docs for badfarm → · Source documentation ↗

goodfarm

Available

Plan, approve, submit, reconcile, and independently verify service repairs through vpscfgfarm. Ships in the badfarm distribution.

Reviewed repair coordination. Docs for goodfarm → · Source documentation ↗

Repair coordination uses explicit protocol operations through vpscfgfarm. A finding recommendation is not converted into an arbitrary shell command. Some host recipes remain gated until the executor supports them.

farmops

Early development

A catalog and loader for routine operations built on badfarm and vpscfgfarm. Scheduling, execution, and reports remain planned.

Routine operations. Docs for farmops → · Source documentation ↗

Current scope is the catalog schema, loader, journal, and test foundations. Compiler, templates, scheduler, runner, and reports are future work.

oos

Available

Find where the disk goes, check policy thresholds, and clean configured paths with quarantine and restore. macOS and Linux.

Disk headroom and cleanup. Docs for oos → · Source documentation ↗

Out of Danger

Available

Check command arguments and protected paths before invoking a configured executable. A safer normal command path, not an unbypassable security boundary.

Command policy wrapper. Docs for Out of Danger → · Source documentation ↗

The underlying executable remains accessible. This wrapper helps prevent mistakes on the normal command path; it does not isolate a hostile user.

opensah

Available

List suite roles and check that sahlink, sahconnect, and sahapi are on PATH. Reports adssh, sahsync and sahxfer without failing.

Local suite index. Docs for opensah → · Source documentation ↗

sahconnect

Available

Make authenticated SystemAPI HTTP requests, or pass SSH arguments through to the installed adssh executable.

SystemAPI and SSH client. Docs for sahconnect → · Source documentation ↗

sahconnect api GET /api/v1/fleet
sahconnect ssh -- version

HTTP uses SYSTEMAPI_URL and SYSTEMAPI_API_KEY. SSH launches SAHCONNECT_ADSSH or adssh on PATH.

sahapi

Available

A bearer-protected loopback service with a suite catalog and three fixed, read-only SystemAPI proxy routes.

Local API service. Docs for sahapi → · Source documentation ↗

sahlink

Available

Launch a process, record stdio, and optionally relay one socket connection. Read capture and write input through a local control socket. Since 0.2.0: forward one TCP port, or RDP, through a host's agent.

Process I/O capture. Docs for sahlink → · Source documentation ↗

sahlink run -- /bin/echo hello

Stderr prints socket and token-file paths. Capture applies only to the process started by this command and the optional configured relay. Captured output can contain secrets printed by the child. Existing-PID attachment and ptrace are unsupported.

sahsync

Available

Copy and sync files and directories through a host's SystemAPI agent: put, get, ls and sync, dry runs, an audit line per change. The SAH replacement for scp, sftp and rsync over SSH.

File copy and sync. Docs for sahsync →

Version 0.1.0, a wired join on SystemAPI's file channel. The repository is not public yet.

sahmesh

Available

A loopback SOCKS5 proxy that reaches every host with a SystemAPI agent by name: one multiplexed WebSocket per host, many TCP streams on it, dialed as NAME.sah:PORT.

Host-by-name proxy. Docs for sahmesh → · Source documentation ↗

sahmesh up
curl --socks5-hostname 127.0.0.1:1080 http://web1.sah:8080/healthz

Version 0.1.0, a wired join on SystemAPI's mesh channel, a phase-0 contract. An IP literal needs a --route CIDR=AGENT; no DNS is resolved and BIND, UDP and reverse listeners are refused.

sahrdp

Early development

Watch a host's desktop. A host daemon records each frame in an HMAC-chained file, then streams view-only JPEG tiles, and audio when the lease grants it, in its own sahrdp/1 protocol. A native viewer for macOS, Linux and Windows shows the stream. This is not Microsoft RDP.

Remote desktop view. Docs for sahrdp → · Source documentation ↗

go build -tags desktop -o sahrdp-gui ./cmd/sahrdp-gui
./sahrdp-gui

The daemon, the viewer and the recording verifier exist. SystemAPI has no display channel yet, so no enrolled host serves a desktop. Input, clipboard and drives are refused.

sahxfer

Early development

Move one large file fast. A grant authorizes the host, path, size and hash; the bytes travel on sahxfer's own UDP plane with ChaCha20-Poly1305, loss repair and pacing.

Bulk file transfer. Docs for sahxfer → · Source documentation ↗

sahxfer recv --grant g.json --listen 0.0.0.0:47100 --root /srv/inbox
sahxfer put --grant g.json --to 203.0.113.9:47100 ./image.bin

Grant-file transfers between two machines work today. The hosted path through the hub and the host agent is not wired yet.

sah2grpc

Early development

gRPC debug tooling for SAH: a loopback daemon that drives adssh sah and a client that prints the recorded decisions.

Decision debugging. Docs for sah2grpc → · Source documentation ↗

Design accepted; protocol definitions and library packages only, no command yet, nothing wired.

systemapi-security (secsvc)

Early development

A local security service for one Linux machine. The binary secsvc serves a Unix-socket API that checks Ed25519 grants, keeps an append-only audit chain with a local anchor and a signed head for off-host witnesses, and runs a host IDS (authentication failures, file integrity, listeners) plus opt-in distro security modules for Debian, Red Hat, Rocky, Ubuntu, Alpine and Arch. High findings page through ntfy without host detail by default.

Host security service. Docs for systemapi-security → · Source documentation ↗

The anchored chain, the signed head and the detail-free pages are on hardening branches, not yet on the default branch. The agent side that collects signed heads, and agent and dashboard integration, are not wired. Root can still rewrite every local file.

sash-init (sahinit)

Early development

A Go userspace service supervisor intended to replace systemd as PID 1: strict JSON units, dependency boot waves, readiness checks, restart limits, explicit execution identities, an optional Landlock sandbox, a cgroup v2 cgroup per service, a local control socket, and signed boot-policy metadata that either never expires, bounded by a signed revocation floor, or must be renewed.

Service supervisor. Guide for sash-init → · Unit reference for sash-init → · Commands, files and codes for sash-init → · Source documentation ↗

It does not replace systemd on a host yet; an experimental PID 1 mode is tested in virtual machines. Boot policy is metadata only and is not enforced. Units can run sash service scripts under signed grants, with test-made grants until a fleet signer exists. These features are on the fix/flaky-tests branch, not yet merged into main.

nftapi

Early development

A localhost JSON API for nftables: one authenticated POST /v1 endpoint with a closed match and verdict language, on a loopback address only, plus built-in threat-indicator feeds that return indicators without changing the ruleset.

Firewall API. Docs for nftapi → · Source documentation ↗

Named sets, for groups and for block and unblock, are planned and not in this build. SystemAPI is a planned client; nothing calls nftapi yet.

sahcore

Unassigned

The name is reserved. No assigned role, binary, or service exists yet.

Reserved component. Docs for sahcore → · Source documentation ↗

Missing Utils

Unreleased

48 small, JSON-native command-line tools: “why” diagnostics that report evidence with explicit gaps, Linux host collectors, a macOS security research suite, binary inspection, and the osx subsystem utility. State-changing actions require an explicit flag such as --apply.

Evidence-first diagnostics. Docs for Missing Utils → · Source documentation ↗

Every command is implemented at a bounded, documented scope and none is released yet. Most host collectors target Linux.

rcdo

Early development

An accessible DevOps toolkit. It pre- and post-processes Terraform, OpenTofu, Ansible, AWS, gcloud and other noisy output through a policy layer, so engineers using screen readers, braille, speech or large print don’t miss what matters.

Accessible change review. Docs for rcdo → · Source documentation ↗

A beta core with no tagged release, licensed GPL-3.0-or-later. It reads Missing Utils evidence such as jsonprobe and contextsnap output.

prtool

Early development

A read-only viewer for GitHub pull requests and GitLab merge requests. It prints one labelled field per line and a diff that keeps its + and - markers, so colour is never the only signal. A piped diff is the applicable patch.

Pull request reading. Docs for prtool → · Source documentation ↗

Version 1.0.0 with no tagged release, licensed GPL-3.0-or-later. It reads through gh and glab and has no JSON output of its own.

Development worktrees

The phase-integration and CI-fix worktrees of vpscfgfarm are development checkouts of the same project. They do not have separate installation paths or product identities.
