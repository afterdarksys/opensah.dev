The tool reference.

What each part does, where it belongs, and where to find its source documentation.

Each tool keeps its own repository and release lifecycle. The farm tools, local utilities and utility suites have full tool guides on this site; follow each repository's source documentation for every flag, configuration key, and policy requirement.

adssh

Available

A programmable shell with policy evaluation, approvals, an HMAC audit chain, Starlark extensions, and an MCP server. The binary remains adssh.

Execution shell. Source documentation ↗

vpscfgfarm

Available

Configuration and deployment gates for SSH fleets. A governor, reviewed contracts, and journals bound every permitted mutation.

Contracted fleet changes. Docs for vpscfgfarm → · Source documentation ↗

badfarm

Available

Inventory and assess hosts, containers, Kubernetes, and infrastructure code. Emit evidence and a reviewable remediation handoff.

Read-only discovery. Docs for badfarm → · Source documentation ↗

goodfarm

Available

Plan, approve, submit, reconcile, and independently verify service repairs through vpscfgfarm. Ships in the badfarm distribution.

Reviewed repair coordination. Docs for goodfarm → · Source documentation ↗

Repair coordination uses explicit protocol operations through vpscfgfarm. A finding recommendation is not converted into an arbitrary shell command. Some host recipes remain gated until the executor supports them.

farmops

Early development

A catalog and loader for routine operations built on badfarm and vpscfgfarm. Scheduling, execution, and reports remain planned.

Routine operations. Docs for farmops → · Source documentation ↗

Current scope is the catalog schema, loader, journal, and test foundations. Compiler, templates, scheduler, runner, and reports are future work.

oos

Available

Find where the disk goes, check policy thresholds, and clean configured paths with quarantine and restore. macOS and Linux.

Disk headroom and cleanup. Docs for oos → · Source documentation ↗

Out of Danger

Available

Check command arguments and protected paths before invoking a configured executable. A safer normal command path, not an unbypassable security boundary.

Command policy wrapper. Docs for Out of Danger → · Source documentation ↗

The underlying executable remains accessible. This wrapper helps prevent mistakes on the normal command path; it does not isolate a hostile user.

opensah

Available

List suite roles and check that sahlink, sahconnect, and sahapi are on PATH. Reports adssh separately.

Local suite index. Source documentation ↗

sahconnect

Available

Make authenticated SystemAPI HTTP requests, or pass SSH arguments through to the installed adssh executable.

SystemAPI and SSH client. Source documentation ↗

sahconnect api GET /api/v1/fleet
sahconnect ssh -- version

HTTP uses SYSTEMAPI_URL and SYSTEMAPI_API_KEY. SSH launches SAHCONNECT_ADSSH or adssh on PATH.

sahapi

Available

A bearer-protected loopback service with a suite catalog and three fixed, read-only SystemAPI proxy routes.

Local API service. Source documentation ↗

sahlink

Available

Launch a process, record stdio, and optionally relay one socket connection. Read capture and write input through a local control socket.

Process I/O capture. Source documentation ↗

sahlink run -- /bin/echo hello

Stderr prints socket and token-file paths. Capture applies only to the process started by this command and the optional configured relay. Captured output can contain secrets printed by the child. Existing-PID attachment and ptrace are unsupported.

sahcore

Unassigned

The name is reserved. No assigned role, binary, or service exists yet.

Reserved component. Source documentation ↗

Missing Utils

Unreleased

48 small, JSON-native command-line tools: “why” diagnostics that report evidence with explicit gaps, Linux host collectors, a macOS security research suite, binary inspection, and the osx subsystem utility. State-changing actions require an explicit flag such as --apply.

Evidence-first diagnostics. Docs for Missing Utils → · Source documentation ↗

Every command is implemented at a bounded, documented scope and none is released yet. Most host collectors target Linux.

rcdo

Early development

An accessible DevOps toolkit. It pre- and post-processes Terraform, OpenTofu, Ansible, AWS, gcloud and other noisy output through a policy layer, so engineers using screen readers, braille, speech or large print don’t miss what matters.

Accessible change review. Docs for rcdo → · Source documentation ↗

A beta core with no tagged release, licensed GPL-3.0-or-later. It reads Missing Utils evidence such as jsonprobe and contextsnap output.

Development worktrees

The phase-integration and CI-fix worktrees of vpscfgfarm are development checkouts of the same project. They do not have separate installation paths or product identities.
