Pick a tool.

Each guide covers requirements, installation, a first session, the main commands and configuration, and links to the full documentation in the tool's public repository.

Fleet gates

vpscfgfarm

A governor, contracts, runbooks, approvals and a journal in front of every command sent to an SSH fleet.

 Discovery

badfarm

Read-only assessment of hosts, containers, Kubernetes and infrastructure code, with stored evidence.

 Repairs

goodfarm

Plan, approve, submit, reconcile and verify service repairs. Ships with badfarm.

 Early development

farmops

The catalog format, loader and journal for routine operations. Scheduling is planned.

 Disk headroom

oos

Free-space checks against a policy, and guarded cleanup into a quarantine you can restore.

 Command safety

Out of Danger

A fail-closed policy wrapper for commands such as rm.

The SAH utilities.

The small programs an operator or agent runs from their own machine against enrolled hosts. One page maps all of them: what exists, what each is for, and which one to reach for.

Shell & API client

sahconnect

Log in, open a shell on a host through its agent, call SystemAPI, or hand arguments to adssh.

 File copy & sync

sahsync

Copy and sync files and directories through the agent. The scp and rsync replacement; repository not public yet.

 Early development

sahxfer

One large file, fast, on its own encrypted UDP plane once a grant allows it.

 Process capture

sahlink

Record a process you start. A TCP forward through a host's agent is written but not yet published.

 Local API

sahapi

A loopback service with the suite catalog and read-only SystemAPI proxies.

 Local index

opensah

What is installed here, and the role and state of every suite name.

 Early development

sah2grpc

gRPC tooling that drives adssh sah and prints the decisions. No command yet.

Utility suites.

Two larger toolkits and a pull request viewer that work on their own, on an engineer’s machine or in CI, rather than through the fleet gates. All three are designed for engineers who use screen readers, braille displays, magnification or large print; see accessible tooling for how they work together.

Unreleased

Missing Utils

48 JSON-native diagnostics, collectors and macOS research tools that report evidence and explicit gaps.

 Accessible operations

rcdo

Policy-driven processing of noisy Terraform, Ansible and cloud output for screen readers and large print.

 Pull requests

prtool

Read-only GitHub pull request and GitLab merge request viewer with labelled fields and a diff that never relies on colour alone.

How they fit together.

badfarm discovers→ goodfarm plans→ vpscfgfarm executes→ badfarm verifies
  • badfarm assesses targets read-only and stores findings with their evidence.
  • goodfarm binds selected findings to a vpscfgfarm service contract, gets the exact request approved by vpscfgfarm, submits it once, and verifies recovery against a later badfarm scan. Today only the service-deploy/v1 recipe executes; distro security upgrades and reboots can be planned and approved, but their execution is refused until it is graduated.
  • vpscfgfarm holds all of the authority. Its governor, deny floor, scopes and postures apply to every request, including goodfarm's.
  • farmops is planned to schedule routine work under standing grants that vpscfgfarm checks on every call. Only its catalog format, loader and journal exist today.
  • oos and Out of Danger work on their own, on one machine. badfarm reports on the oos hourly agent where it is installed.
  • Missing Utils collects and normalizes evidence; rcdo interprets it and makes it navigable. The two share a roadmap, and neither integrates with the farm tools.
  • prtool shows pull and merge requests from gh and glab; its patches can be piped to rcdo diff-walk.
