Wire and network constraints

sahxfer uses wire version 1, a 64-byte header and a 16-byte AEAD tag. The grant selects internet (1,232-byte datagram / 1,152-byte plaintext) or dc (8,192 / 8,112). There is no v1 path-MTU probing. A large-profile path must actually support the selected datagrams; it is not automatically faster.

UDP reachability is required. A listening peer needs a reachable address; NAT without an exposed port requires an appropriate relay route. A relay forwards sealed packets and cannot decrypt file contents. Blocked UDP does not trigger an automatic CLI QUIC or TCP fallback.

The QUIC library requires TLS 1.3, ALPN sahxfer/1 and no 0-RTT; those library properties do not make QUIC a supported CLI option. pace-bbr is the implementation's tested controller subset, not a byte-identical BBRv3 implementation.

sahsync's path and name rules include case/Unicode collision checks for downloads and reserved temp names. Do not assume that an scp-style command means every filename or metadata field is portable.

Before claiming interoperability

Record exact client, server and helper revisions; OS/kernel; transport/profile; path policy; and tested put/get cases. Run negative cases for wrong grants, unsupported versions, replay, tampered data, expiry, hash mismatch and path escape. Publish tested combinations with dates. A schema document alone is not interoperability evidence.
