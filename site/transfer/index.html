Two tools, two jobs

Need Tool Contract
Copy files or synchronize a directory tree through an enrolled host sahsync Sequential file operations over the SystemAPI agent WebSocket
Transfer one large regular file on a separate encrypted data plane sahxfer One file, one direction, one grant; UDP in the CLI
Continuous processed events with durable replay Proposed streaming extension Local storage prototype exists; no network stream service

sahxfer separates permission from payload transport. SystemAPI authorizes the host, purpose, path, size, hash and lifetime. The peers then move encrypted bytes directly or through a relay. File bytes do not burden the agent's existing WebSocket. A relay forwards sealed datagrams without the file key.

Start here

  • Run a transfer or integrate an agent.
  • Implement the v1 wire contract, including packet layout, repair, cryptography and completion.
  • Understand the control API and helper lifecycle.
  • Check compatibility and limits before choosing a transport or operating system.
  • Handle cancellation, retries and commit uncertainty.
  • Read the performance evidence and the experimental roadmap.
  • Use sahsync, review its path rules, or read the agent file protocol.

What “faster” means here

The engineering work reduces allocation, batches socket operations, buffers source reads, repairs missing ranges, and paces packets with feedback. Encryption, file verification and commit remain part of the transfer. Report end-to-end goodput including preparation and durable commit, alongside transfer-only measurements.

Local benchmarks show improvements over earlier sahxfer revisions. They do not establish superiority over SCP, SFTP, FTP or HTTPS, Internet fairness, or 10/25/100 Gbit/s performance. Those comparisons need equivalent workloads and security/durability settings.

Implementation is not deployment

The UDP engine and local grant-file workflow exist. The helper control interface also exists. This documentation does not certify a particular SystemAPI deployment or agent version as integrated. Check the deployed pair before using the HTTP grant workflow. QUIC is library-only in the current CLI; durable streaming is a separate proposed network contract.
