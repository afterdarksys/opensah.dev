Experiments and the streaming roadmap

A measured file-transfer baseline, a local durable-log prototype, and explicitly separate future network contracts.

Implemented baseline

The v1 CLI transfers one granted file over encrypted UDP. Performance work includes bounded source read-ahead, packet-buffer reuse, reusable crypto scratch and socket batching. put --pipeline-source is an opt-in experiment; current local measurements do not establish a meaningful end-to-end gain from enabling it. See the measurements.

Research, not negotiated v1 features

Content-defined chunking, authenticated chunk manifests, alternative cryptographic file hashes, verified resume, compression, MTU negotiation and deeper disk/crypto pipelines need separately specified and tested contracts. Do not add an undocumented DATA flag or silently change a grant digest. A non-cryptographic lookup hash cannot authorize content reuse.

Optimizations must keep bounded queues, explicit buffer ownership, unique nonces, authenticated bytes, hash verification and commit. Shared-link fairness and storage bottlenecks matter alongside goodput.

Durable processed events: local prototype

A local streamlog library and synthetic streamlab harness exist. They exercise immutable segments, checkpoints, producer epochs, exact retry deduplication, bounded replay and distinct persisted/processed cursors. They have no network listener, stream grants, replication or retention eviction. The prototype stores plaintext locally.

# From the sahxfer repository; synthetic local data only.
go run ./cmd/streamlab -records 1024 -record-bytes 4096 -batch 64

The proposed network service needs its own grants, consumer authorization, framing, credit, reconnect keys and replay policy. v1 file grants do not authorize streams. A transport receipt is not an exactly-once business effect.

Release tracks

Track Delivery goal State
Single files Verified content and explicit commit Implemented baseline; deployment integration must be checked
Durable processed events Ordered partitions, persisted acknowledgments, replay and explicit gaps Local storage prototype; network integration proposed
Fresh-update analytics Explicit supersession, bounded staleness and snapshot recovery Future track
AI datasets/checkpoints Versioned manifests, verified resume and atomic dataset publication Future track; single files already supported

Before a network streaming release: specify authorization and recovery; test crash boundaries and corrupted history; bound spools and queues; define retention and disk-full behavior; validate cancellation and fresh keys on reconnect. Production deployment also needs storage protection and operational evidence appropriate to the workload.

Read the complete local prototype and proposed streaming contract. Release dates and performance SLOs are not established here.
