The intended lifecycle

Provision→ Enroll→ Authorize→ Execute→ Verify

Automatic ComputeAPI-to-SystemAPI enrollment and SystemAPI-to-adssh lease handoff are not implemented. The initial sah/1 frame does not connect those steps.

Execution and authority

The SystemAPI agent and adssh remain separate programs. SystemAPI uses its outbound agent for entitled workload operations. adssh supplies shell execution and policy; break-glass integration stays a child-process boundary.

vpscfgfarm owns its governor and contracted mutation path. goodfarm coordinates approved protocol requests rather than inventing commands from findings. farmops is designed to propose and schedule work under that existing authority.

Identity is not interchangeable.

SystemAPI hosts device login. adssh is a client of that flow. Dashboard login uses Authentik. The opaque CLI bearer, a dashboard access token, a local sahapi bearer, and a provider API key serve different purposes.

sahapi does not host OAuth. Its server-side SystemAPI key is separate from the bearer presented by a local caller.

Bare metal needs a lifecycle.

The planned offering combines capacity allocation with enrollment, policy-controlled operations, and cleanup. Physical power control and imaging require a provisioning adapter in addition to a reachable execution shell. Dedicated hosts and shared container capacity will need separate isolation and allocation contracts.
